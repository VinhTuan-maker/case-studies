Getting reliable work out of a 4B modelKhiến một mô hình 4B làm việc đáng tin cậy

The problem: a platform runs the same small text jobs on every product, company and article: removing contact details, extracting attributes, cleaning titles, writing short summaries. Paying a cloud model for each of those calls adds up. I moved more than fifteen of these tasks to a 4-billion-parameter model on our own GPU server, and learned how to write prompts and code around a model that is fast and cheap but easily confused.

Bài toán: một nền tảng chạy cùng những việc xử lý văn bản nhỏ trên mọi sản phẩm, doanh nghiệp và bài viết: gỡ thông tin liên hệ, trích thuộc tính, làm sạch tiêu đề, viết tóm tắt ngắn. Trả tiền mô hình cloud cho từng lượt gọi cộng lại rất tốn. Tôi chuyển hơn mười lăm việc như vậy sang một mô hình 4 tỷ tham số chạy trên GPU server riêng, và học được cách viết prompt và code bao quanh một mô hình nhanh, rẻ nhưng dễ bị rối.

The problemBài toán

Small models fail in predictable waysMô hình nhỏ thất bại theo những cách đoán trước được

A 4B model is fast, cheap to run on one GPU, and keeps data in-house. But with the same prompts that work on a large cloud model, it went wrong in the same few ways again and again:

Mô hình 4B chạy nhanh, rẻ trên một GPU, và giữ dữ liệu trong nội bộ. Nhưng với cùng những prompt chạy tốt trên mô hình cloud lớn, nó sai lặp đi lặp lại theo vài kiểu giống nhau:

It "improves" the textTự ý "cải thiện" văn bảnAsked to delete one thing, it also rewrites, summarizes or adds a comment.Được bảo xoá một thứ, nó viết lại, tóm tắt hoặc thêm bình luận.
It invents numbersTự bịa số liệuRounds to a "nicer" figure, adds percentages together, or copies a number from the example.Làm tròn cho "đẹp", cộng các tỷ lệ % với nhau, hoặc chép số từ ví dụ.
It loses track of rulesQuên luậtWith many interacting rules, it follows the first few and forgets the rest.Khi có nhiều luật đan xen, nó làm theo vài luật đầu và quên phần còn lại.
It breaks the formatLàm hỏng định dạngExtra braces, markdown fences, or eight paragraphs where three were asked for.Thừa dấu ngoặc, bọc trong khối markdown, hoặc tám đoạn khi chỉ yêu cầu ba.

The fix was rarely a cleverer prompt. It was a different split of work between the model and the code around it.

Cách sửa hiếm khi là một prompt khéo hơn. Mà là chia lại việc giữa mô hình và phần code bao quanh nó.

Level 1 · Technique 1Cấp 1 · Kỹ thuật 1

Don't ask the model what code already knowsĐừng hỏi mô hình điều code đã biết

Gate beforeLọc trướcA regular expression checks for phone numbers, emails and messaging handles first. Text without any is returned untouched, so most descriptions never reach the model at all. The phone pattern was later tightened so specs like "10000–20000 MT" don't look like phone numbers.Một biểu thức chính quy kiểm tra số điện thoại, email và tài khoản nhắn tin trước. Văn bản không có gì thì giữ nguyên, nên phần lớn mô tả không bao giờ tới mô hình. Mẫu số điện thoại sau đó được siết lại để thông số như "10000–20000 MT" không bị nhận nhầm.
LookupsBảng traValues like "n/a", "tbd" or "any" are dropped by a plain list before the prompt. That is not a judgment call, so it shouldn't take up the model's attention.Các giá trị như "n/a", "tbd" hay "any" được loại bằng một danh sách đơn giản trước khi vào prompt. Đây không phải việc cần phán đoán, nên không nên chiếm sự chú ý của mô hình.
Mechanical rules afterLuật máy móc làm sauA rule like "drop a combined value when its parts are already listed" was taken out of the prompt and done in code after the call. Code applies it every time, however the model reasoned.Luật kiểu "bỏ giá trị gộp khi các phần của nó đã có trong danh sách" được rút khỏi prompt và làm bằng code sau lượt gọi. Code luôn áp dụng đúng, bất kể mô hình suy luận ra sao.
FormattingĐịnh dạngShortening long values, building the final "keyword | phrase | site" title, wrapping paragraphs in HTML: all moved from instructions into code.Rút gọn giá trị dài, ghép tiêu đề cuối "từ khoá | cụm từ | tên trang", bọc đoạn văn bằng HTML: tất cả chuyển từ lời dặn sang code.
Level 1 · Technique 2Cấp 1 · Kỹ thuật 2

Shrink the task until it fitsThu nhỏ việc cho tới khi vừa sức

Each call does one job, and the prompt says what must stay the same and what to return when there is nothing to do. A small model needs that "do nothing" path spelled out; otherwise it always changes something.

Mỗi lượt gọi làm đúng một việc, và prompt nói rõ phần nào phải giữ nguyên, phải trả về gì khi không có gì để làm. Mô hình nhỏ cần được chỉ rõ đường "không làm gì"; nếu không, nó luôn thay đổi một thứ gì đó.

Too broad for 4B (illustrative)Quá rộng với 4B (minh hoạ)
Clean up this product title and make it better for SEO.

The model rewrites the whole title, and the result changes from run to run.Mô hình viết lại cả tiêu đề, và kết quả thay đổi mỗi lần chạy.

Narrow (illustrative)Hẹp (minh hoạ)
Remove ONLY a trailing date or period (e.g. "– Q3 2026", "(Sep 2026)"). Keep every other word exactly as written. If there is no date at the end, return the title exactly as given. "Rice Prices – Sep 2026" → "Rice Prices" "Organic Cashew W320" → "Organic Cashew W320"
  • One item per call. FAQs are generated one question at a time instead of "write 5 FAQs", so each answer stays focused on its own question.Mỗi lượt một mục. FAQ được sinh từng câu một thay vì "viết 5 FAQ", nên mỗi câu trả lời chỉ tập trung vào câu hỏi của nó.
  • Small pieces of input. To remove contact details from an HTML description, the code splits it into text nodes and sends each one separately, in parallel. The model never sees markup, so it cannot break the layout; code removes nodes that come back empty.Đầu vào nhỏ. Để gỡ thông tin liên hệ khỏi mô tả HTML, code tách thành từng đoạn văn bản và gửi riêng từng đoạn, song song. Mô hình không bao giờ thấy thẻ HTML nên không thể làm vỡ bố cục; code tự xoá các đoạn trả về rỗng.
Level 2 · Technique 3Cấp 2 · Kỹ thuật 3

Show, don't explainCho xem, đừng giải thích

A small model copies a pattern far better than it follows an abstract rule. When a long list of instructions kept being half-followed, replacing most of it with a few well-chosen input → output pairs worked better, and the prompt got shorter.

Mô hình nhỏ bắt chước khuôn mẫu tốt hơn nhiều so với làm theo một luật trừu tượng. Khi một danh sách dài chỉ dẫn cứ bị làm theo một nửa, thay phần lớn bằng vài cặp đầu vào → đầu ra được chọn kỹ lại hiệu quả hơn, và prompt còn ngắn đi.

Instructions only (illustrative)Chỉ có chỉ dẫn (minh hoạ)
Keys must be short noun phrases in Title Case. Do not include units in the key. Put units in the value. Merge synonyms. Never output product name, price, quantity or port as keys. Normalise percentages. Keep original spelling of grades and varieties…
Mostly examples (illustrative)Chủ yếu là ví dụ (minh hoạ)
"Moisture max 14%, broken 5%, crop 2026" → [{"key":"Moisture","value":"Max 14%"}, {"key":"Broken","value":"5%"}, {"key":"Crop Year","value":"2026"}] "ST25 rice, 25 MT, FOB HCMC, USD 780" → [{"key":"Variety","value":"ST25"}] (quantity, port and price are not attributes)
  • Let one example teach several rules. The second example above shows "skip price, quantity and port" without a rule saying so.Để một ví dụ dạy nhiều luật. Ví dụ thứ hai ở trên cho thấy "bỏ giá, số lượng và cảng" mà không cần một luật nào nói ra.
  • Keep the rules that examples can't show. Hard limits such as "never invent a number" stay as one-line rules; style and naming are taught by example.Giữ lại những luật mà ví dụ không thể hiện được. Giới hạn cứng như "không bao giờ bịa số" vẫn là luật một dòng; còn văn phong và cách đặt tên thì dạy bằng ví dụ.
  • Vary the examples on purpose. Different domains and lengths, so the model learns the pattern rather than the wording of one example.Chủ động làm ví dụ đa dạng. Khác lĩnh vực, khác độ dài, để mô hình học khuôn mẫu chứ không học thuộc câu chữ của một ví dụ.
Level 2 · Technique 4Cấp 2 · Kỹ thuật 4

Write rules a small model can holdViết luật mà mô hình nhỏ nhớ được

Short, numbered, self-containedNgắn, đánh số, độc lậpOne constraint per rule and no "see rule 3". On one task I cut the rules from nine to six and moved the rest into code.Mỗi luật một ràng buộc, không "xem luật 3". Ở một việc, tôi cắt từ chín luật xuống sáu và chuyển phần còn lại sang code.
Concrete limitsGiới hạn cụ thể"Copy each number exactly", "never add two percentages", "say 'most' only above 50%" work better than "be accurate"."Chép đúng từng con số", "không cộng hai tỷ lệ %", "chỉ nói 'phần lớn' khi trên 50%" hiệu quả hơn "hãy chính xác".
Repeat the critical rule lastNhắc lại luật quan trọng ở cuốiA short "final reminder" at the end of the prompt, because small models tend to follow what they read last.Một dòng "nhắc lại lần cuối" ở cuối prompt, vì mô hình nhỏ có xu hướng làm theo điều được đọc sau cùng.
Examples for the edgesVí dụ cho tình huống biênInclude the "nothing to change" case, the "everything must go" case, and the case where the thing to remove is at the start.Có ví dụ "không cần đổi gì", "phải xoá hết", và trường hợp phần cần xoá nằm ngay đầu câu.
Examples that can't leakVí dụ không thể bị chépA realistic price in an example ended up in real outputs. Examples now use obvious placeholders such as "USD 1,234–5,678", labelled as patterns only.Một mức giá trông như thật trong ví dụ đã lọt vào đầu ra thật. Giờ ví dụ dùng số giữ chỗ dễ nhận ra như "USD 1,234–5,678", ghi rõ chỉ là khuôn mẫu.
Thinking, made explicitSuy nghĩ, viết ra rõ ràngFor a keep/remove decision, the model writes one short line per item ("value → KEEP, rule 2") and then the answer after a FINAL: marker, which code splits on.Với việc giữ/bỏ, mô hình viết mỗi mục một dòng ngắn ("giá trị → KEEP, luật 2") rồi đưa đáp án sau dấu FINAL:, code tách theo dấu này.

Level 3 · Technique 6Cấp 3 · Kỹ thuật 6

Order the prompt for the cacheSắp xếp prompt để tận dụng cache

The self-hosted inference server can reuse the work it already did for the beginning of a prompt, as long as that beginning is identical from one request to the next (prefix caching). The same task runs thousands of times with the same instructions and examples and only the record changes, so the order of the prompt decides how much of that work is reused.

Server suy luận tự host có thể dùng lại phần tính toán đã làm cho đoạn đầu của prompt, miễn là đoạn đầu đó giống hệt nhau giữa các lượt gọi (prefix caching). Cùng một việc chạy hàng nghìn lần với cùng chỉ dẫn và ví dụ, chỉ có bản ghi thay đổi, nên thứ tự trong prompt quyết định phần tính toán được dùng lại nhiều hay ít.

Cache-unfriendlyKhông hợp với cache
Product: {this record} ← changes every call Style: {random angle} ← changes every call Rules: … Examples: …

The first line already differs, so nothing after it can be reused.Ngay dòng đầu đã khác, nên không phần nào phía sau được dùng lại.

Cache-friendlyHợp với cache
[system] Role, rules, examples ← identical every call [user] Style: {random angle} Product: {this record} ← only this part is new

The long fixed part is computed once and reused; each call only processes the short new tail.Phần cố định dài chỉ tính một lần rồi dùng lại; mỗi lượt gọi chỉ xử lý đoạn đuôi ngắn mới.

  • Static first, variable last. Role, rules and examples go in the system message, word for word the same every time; the record goes at the very end of the user message.Phần cố định trước, phần thay đổi sau. Vai trò, luật và ví dụ nằm trong system message, giống hệt nhau từng chữ mỗi lần; bản ghi nằm ở cuối cùng của user message.
  • Keep randomness out of the prefix. Random style angles, shuffled fields, dates or IDs belong after the fixed part; one changing word near the top breaks the cache for everything below it.Để phần ngẫu nhiên ra khỏi đoạn đầu.   • It also makes long example lists affordable. Cut long input into small callsCắt đầu vào dài thành nhiều lượt gọi nhỏ

A 4B model reads a short input well and a long one badly. With a long description it can keep the first rules and forget the rest, edit the wrong paragraph, or break the HTML around the text it was asked to touch. So long input is never sent whole: code splits it, trims it, or sends it to a bigger model.

Mô hình 4B đọc đầu vào ngắn rất tốt và đầu vào dài thì kém. Với một mô tả dài, nó có thể nhớ mấy luật đầu và quên phần sau, sửa nhầm đoạn, hoặc làm hỏng HTML quanh phần chữ được yêu cầu sửa. Vì vậy đầu vào dài không bao giờ được gửi nguyên: code tách nhỏ, cắt bớt, hoặc chuyển sang mô hình lớn hơn.

  • Split by structure, not by length. Level 5 · Technique 8Cấp 5 · Kỹ thuật 8

Every number in the output is read from the input, never calculated by the model. Before the call, code computes the figures, drops zeros and tiny shares, and turns raw percentages into labels such as major or medium. Counts that the model tended to misuse are simply not shown to it.

Mọi con số ở đầu ra đều được đọc từ đầu vào, không bao giờ do mô hình tự tính. Trước khi gọi, code tính sẵn các số, bỏ số 0 và tỷ trọng quá nhỏ, rồi đổi tỷ lệ % thô thành nhãn như major hay medium. Những con số mô hình hay dùng sai thì đơn giản là không đưa cho nó.

Level 6 · Knowing the limitCấp 6 · Biết giới hạn

When 4B is the wrong modelKhi 4B là lựa chọn sai

Not everything belongs on the small model. A lead-quality check that weighs many signals at once started on the 4B model and moved to a cloud model the same day, because the judgment was too broad for it. The rule I settled on: the 4B model gets high-volume tasks with a narrow, checkable answer; anything that needs open-ended judgment or reads long documents goes to a larger model.

Không phải việc gì cũng hợp với mô hình nhỏ. Một bước đánh giá chất lượng lead cần cân nhắc nhiều tín hiệu cùng lúc ban đầu chạy trên mô hình 4B, rồi chuyển sang mô hình cloud ngay trong ngày vì việc phán đoán quá rộng. Nguyên tắc tôi rút ra: mô hình 4B nhận việc số lượng lớn có đáp án hẹp và kiểm tra được; việc cần phán đoán mở hoặc đọc tài liệu dài thì dùng mô hình lớn hơn.

Testing prompts like codeKiểm thử prompt như kiểm thử code

For the attribute-cleaning task I set up a promptfoo comparison of two prompt styles, a long prose version and a short "rules as code" version, against the production model with the same settings production uses. Each test case lists values that must be kept, removed or merged, with ambiguous values deliberately left unscored.

LessonsBài học

What I would tell the next personĐiều tôi muốn chia sẻ

With a small model, every rule you can move into code is a rule the model can no longer break.Với mô hình nhỏ, mỗi luật bạn chuyển được sang code là một luật mô hình không còn làm sai được nữa.

  • Fix the input, not just the prompt. Renaming a field or hiding a number solved problems that more instructions couldn't.Sửa đầu vào, không chỉ sửa prompt. Đổi tên một trường hay ẩn một con số giải quyết được những việc mà thêm lời dặn không làm được.
  • Design for "nothing to do". The most common real input needs no change. A prompt without a clear no-op path will change it anyway.Thiết kế cho trường hợp "không có gì để làm". Đầu vào phổ biến nhất trong thực tế lại không cần thay đổi gì. Prompt không có lối "giữ nguyên" rõ ràng sẽ vẫn thay đổi nó.
  • Examples beat explanations. When a small model ignores a rule, try showing it instead of rewording it.Ví dụ hiệu quả hơn giải thích. Khi mô hình nhỏ bỏ qua một luật, hãy thử cho nó xem ví dụ thay vì viết lại câu chữ của luật.
  • Prompt order is a performance setting. Fixed instructions first and the changing record last turned the shared part of every prompt into cached work.Thứ tự prompt cũng là một thiết lập hiệu năng. Chỉ dẫn cố định đặt trước, bản ghi thay đổi đặt sau, biến phần dùng chung của mọi prompt thành phần đã được cache.
  • Always have a way out. A cloud fallback and a safe default made it acceptable to run a 4B model on pages real customers see.Luôn có lối thoát. Phương án dự phòng trên cloud và giá trị mặc định an toàn khiến việc chạy mô hình 4B trên các trang khách hàng thật nhìn thấy trở nên chấp nhận được.
